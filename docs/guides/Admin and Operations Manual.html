Admin and operations manual

For institution admins, IT, registrar leads and Semester support staff. Pilot edition, October 2026. Procedures here match the console screens in ui_kits/console and the runbooks in docs/operate. Where they disagree, the runbook wins.

Three rules. The institution owns its records; Semester mirrors them. Company staff never see student records without an approved, time-limited access grant. Every change you make is written to the audit log with your name.

2. First-week setup checklist

  1. Console → Identity. Upload IdP metadata, test sign-in with two test accounts, then turn on enforced SSO.
  2. Console → Roles. Map IdP groups to Semester roles. Check the preview: it lists how many people land in each role before you save.
  3. Console → Integrations. Connect the SIS read feed and LMS. Run a dry sync; review the reconciliation report before the first live sync.
  4. Console → Features. Choose what is on: Ask Semester, community, marketplace, mentorship. Everything starts off.
  5. Console → AI policy. Set the institution default (allowed, guided, off). Faculty can be stricter per course, never looser.
  6. Console → Branding. Upload the mark, choose the accent. Contrast is checked automatically.
  7. Console → Admins. Add at least two admins so you never lock yourself out.

3. Daily operations

Morning check (10 minutes)

  • Integration health: last SIS sync time and error count. Anything older than the agreed window is a P3 ticket.
  • Reconciliation queue: clear or assign new mismatches. Target: none older than 2 business days.
  • Moderation queue (if community is on): reports older than 24 hours get escalated.
  • Support inbox: tickets past their first-response target.

Reconciling a mismatch

  1. Open the item. It shows the SIS value, the Semester value and when each changed.
  2. If the SIS is right, choose Accept SIS. Semester updates on the next sync.
  3. If the SIS is wrong, choose Flag to source office. Semester never overwrites the SIS.
  4. Add a note. The item, your decision and the note go to the audit log.

Changing a feature flag

Flags take effect within 5 minutes. Turning a feature off hides it but keeps data until the retention period ends. Announce student-facing changes 48 hours ahead using the template in Help → Announcements.

4. People and access

  • New staff: add them to the right IdP group. Do not create local accounts.
  • Leavers: remove from IdP; sessions end within 15 minutes via SCIM. Check Console → Sessions to confirm.
  • Delegated access (a TA covering a section): Console → Delegations, choose scope and an end date. Maximum 120 days.
  • Support access to student data: Semester support requests it; an institution admin approves it for one case and a fixed window. Every view is logged and listed for the student in their access history.

7. Support desk procedures (Semester staff)

  1. Acknowledge using the matching macro (docs/operate/Runbooks.html).
  2. Reproduce with a test account on the test campus, never a real student account.
  3. If you need real data, request an access grant. No grant, no look.
  4. Fix, or hand to engineering with steps, expected and actual results.
  5. Close only after the reporter confirms, or after 5 business days with two follow-ups.

8. Term-change procedures

  • 4 weeks before registration: confirm term calendar and hold sources with the registrar; run a readiness dry run.
  • Add/drop week: SIS sync interval shortened; on-call watches reconciliation volume.
  • End of term: archive course communities per policy; run access review (Console → Access review) and remove stale delegations.

9. Quarterly reviews

  • Access review: every admin and delegated role confirmed or removed.
  • Audit log sample: 25 random entries checked for correct actor and reason.
  • Subprocessor list and DPA: any changes notified 30 days ahead.
  • Accessibility spot check: five most-used screens with a screen reader.

10. Contacts

Fill in at kickoff: institution primary admin, IT contact, registrar lead, student affairs lead, counsel, Semester account lead, Semester emergency line. Keep this page printed with the contacts filled in.
