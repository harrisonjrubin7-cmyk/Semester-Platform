Tutorials

Step-by-step walkthroughs. Each takes 5–15 minutes. Students, staff and new developers. Pilot edition, October 2026.

Students

S1. Your first five minutes

  1. Open Semester and choose Sign in with your school.
  2. On Today, read the top card. It is the most urgent thing, with its source.
  3. Tap the source label (◆ Official, ⇄ Connected) to see where it came from.
  4. Go to You → Notifications and pick how you want to be reached.
  5. Done when Today shows your courses and at least one deadline.

S2. Check you can register

  1. Open Plan → Registration.
  2. Look at the readiness checklist. Each line names the office that owns it.
  3. For a red line, tap What to do. It links to that office.
  4. When every line is green, your window time appears. Add it to your calendar.

S3. Study with Ask Semester

  1. Open a course, then Ask.
  2. Check the policy banner. Your instructor decides what help is allowed.
  3. Ask a question about the material. Answers cite the course source.
  4. Do not paste grades, IDs or other records. Semester will block them.

S4. Sell a textbook safely

  1. Marketplace → Sell, then scan the ISBN or type the title.
  2. Set a price and choose a safe meet-up spot from the list.
  3. Accept an offer in chat; pay and get paid in the app.
  4. Mark it handed over. Report anything off with Report.

S5. Control your privacy

  1. You → Privacy & data.
  2. Set who sees each profile field.
  3. Review Access history: every staff view of your data is listed.
  4. Export your data or reset personalisation any time.

Staff

T1. Advisors: work your caseload

  1. Open Caseload. Students are sorted by need, with the reason.
  2. Open a student. Check the source of each flag.
  3. Write a note. Choose Shared if the student should see it.
  4. Set a follow-up date. It returns to your queue then.

T2. Faculty: set your course AI policy

  1. Open your course, then Settings → AI policy.
  2. Choose allowed, guided (hints only) or off, per assignment type if needed.
  3. Add approved sources (syllabus, readings).
  4. Save. Students see the policy banner immediately.

T3. Registrar: clear the reconciliation queue

  1. Console → Reconciliation. Sort by oldest.
  2. For each item compare SIS and Semester values.
  3. Accept SIS, or flag to the source office.
  4. Aim for zero items older than two business days.

T4. Student affairs: run a moderation shift

  1. Ops → Trust & safety → Queue.
  2. Open the oldest report. Read the context, not just the post.
  3. Choose: no action, remove, warn, restrict or escalate. Pick the policy reason.
  4. Urgent safety risk: use Escalate now, which follows your campus protocol.

T5. Admins: add a TA with delegated access

  1. Console → Delegations → New.
  2. Pick the person, the course section and the scope.
  3. Set an end date (max 120 days).
  4. The TA sees the section on next sign-in; it ends automatically.

New developers

D1. Run Semester locally (30 minutes)

  1. Clone the repo, install Node 20 and the Supabase CLI.
  2. cp .env.example .env.local and fill local values only.
  3. supabase start then supabase db reset. This runs migrations 010–080 and the seed.
  4. npm run dev. Sign in as a seeded test student (see tests/helpers.ts).
  5. Done when Today renders for the test student on Test Campus A.

D2. Prove RLS before you ship

  1. Write the policy in a new migration; never edit an applied one.
  2. Add a test in tests/: one allowed actor, one blocked actor from another campus.
  3. npm run test:rls. Both must pass.
  4. Open a PR. CI runs the security job; it must be green.

D3. Add a write command

  1. Writes go through an api.* function, not a table insert.
  2. Validate input, check campus and role, rate-limit, write an audit row.
  3. Add a test to tests/commands.test.ts for success, wrong campus and over-limit.

D4. Call the AI gateway

  1. Use app/api/ai/route.ts only; never call a model provider directly.
  2. Pass course id and approved sources. The gateway applies policy and redaction.
  3. Add a red-team case if you add a new prompt type.

D5. Use a design-system component

  1. Find it in the Design System tab; read its card for props and states.
  2. Import from the bundle; do not copy styles.
  3. Check all six states (default, loading, empty, error, permission, offline).
