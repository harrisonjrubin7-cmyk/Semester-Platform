# Embedded finance roadmap

_Semester native finance · 2026-10-05 · Draft for review by a qualified accountant, payments counsel and security lead. Prototype: ui_kits/native-finance/. Code: handoff/semester-platform (090, lib/payments, webhook route, tests/finance.test.ts)._



| Stage | Semester owns | Rail handles |
|---|---|---|
| 1 Launch | Pricing, checkout, invoices, subscriptions, entitlements, ledger, reconciliation UI | Authorization, card/ACH, settlement |
| 2 Multi-rail | Abstraction, routing, plans, institutional invoicing, fraud workflow | Several rails |
| 3 Embedded finance | Wallet/credits, campus commerce, sub-merchant onboarding, marketplace payouts, revenue share | Licensed partner |
| 4 Payments platform | Risk, routing, treasury, merchant ops | Banks/networks |
| 5 Regulated entity | Direct processing where justified | Direct relationships |

Stage 4–5 needs banking partners, acquiring, PCI DSS program, HSM tokenization, fraud, KYC/KYB, AML/sanctions, licensing, treasury, 24/7 payment incident response, external audit. It is a possible future subsidiary, not a launch dependency.
