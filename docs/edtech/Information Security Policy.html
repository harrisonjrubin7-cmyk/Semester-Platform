Information Security Policy

The rules every Semester person and system follows · Draft · October 2026

Internal policy draft. Approved by the founder; reviewed annually.

1. Scope and ownership

Applies to all employees, contractors, systems and data. Owner: Security lead (founder until hired). Exceptions need written approval, an expiry date and an entry in the exception register.

2. Data classification

ClassExamplesHandling
RestrictedEducation records, grades, financial accounts, health or disability data, credentialsEncrypted, least privilege, logged access, never in logs or analytics, U.S. regions

3. Access control

  • SSO with MFA for every company system; hardware keys for production access
  • Least privilege; production access by time-boxed, ticketed request
  • Quarterly access reviews; same-day removal on departure
  • No shared accounts; service accounts owned and rotated

4. Engineering

  • All changes through reviewed pull requests with CI (tests, dependency and secret scanning)
  • Row-level security on every tenant table; deny by default
  • Secrets only in the platform secret manager
  • Synthetic data only outside production

5. Operations

  • Encryption: TLS 1.2+ in transit; AES-256 at rest
  • Backups daily, restore tested quarterly
  • Logging and monitoring per the Logging Standard; alerts routed to on-call
  • Vulnerabilities fixed: critical 7 days, high 30, medium 90

6. People

  • Background checks where lawful for roles touching restricted data
  • Security and FERPA training at hire and yearly
  • Confidentiality and IP Assignment signed before access

7. Incidents

Report suspected incidents immediately to security@semester.app or the on-call channel. Follow the Incident Response Runbook; customer notice per contract and law.
