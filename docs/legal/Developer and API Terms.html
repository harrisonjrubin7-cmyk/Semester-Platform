Developer and API Terms

Apply to anyone building on Semester's APIs or listing an app · Version [1.0] · Effective [date]

Draft for review by a licensed attorney. Not legal advice. Brackets [ ] mark details to fill in. Check state law, institutional procurement rules and any counterparty paper before use.

1. Access

Semester issues API credentials per app. Each app declares the scopes it needs. An institution must approve an app before it can read any of that institution's data, and can revoke it at any time.

2. Data rules

  • Request the fewest scopes the feature needs. Unused scopes are removed at review.
  • Use data only for the feature the institution approved; never sell it, use it for advertising, or train general-purpose models on it.
  • Delete data within [30] days of an institution revoking the app.
  • Keep credentials secret; never embed them in browser or mobile code.

3. Review and monitoring

Apps are reviewed before listing and when scopes change. Semester logs API calls per app and may suspend an app that exceeds its scopes, rate limits or these terms.

4. Rate limits and changes

Published rate limits apply. Semester gives [90] days' notice before removing or breaking a stable API version, except for security fixes.

5. Security reports

Report vulnerabilities to security@[domain]. Notify Semester within [24] hours of any suspected exposure of Semester data.

6. Liability

APIs are provided as is. Developer is responsible for its app and indemnifies Semester for claims arising from the app's misuse of data.
