## Review sequence

1. Resolve policy/contract conflicts and source authority; inventory/classify data.
2. Review security/privacy, tenant isolation, identity, supplier controls and lifecycle requirements.
3. Review engineering release gates, accessibility, audit/controlled actions, observability and recovery.
4. Approve AI policy hierarchy, provider/data boundaries, evaluation and red-team scope.
5. Review academic domain workflows jointly with SIS/system owners and faculty/registrar representatives.
6. Execute sandbox tests and drills; collect independent dated evidence; remediate and retest.
7. Approve exact tenant/domain activation only after scoped gate satisfaction. Native record replacement requires a separate authority-transfer decision.

## Checklist operation

For each check supply actual owner, target tenant/environment/artifact, evidence reference, test result, reviewer and due date. Permitted outcomes: Not assessed, Pass, Fail, Not applicable with approved rationale. An unread or untested control is not passed. Critical tenant isolation, prohibited data egress, unauthorized official action, or integrity defects block relevant activation. Document any permissible lower-risk exception with compensating control, owner, expiry and re-review.

The specifications reference actual project excerpts but invent no verified endpoints, test results or deployment status. Proposed record fields are design contracts. Source citations in reviews identify the inspected project excerpts.
