Phase one: the student–faculty foundation

Establish the shared foundation and deploy one verified student–faculty academic workflow on it — without a second application, duplicate institutional records, or turning the prototype catalog into a production claim. Schema names, routes and gates are proposals until reconciled against the repository.

Status. Signed paid pilot with Vanderbilt — launch Spring 2027, pending institutional activation. Nothing in this document has been executed. A runnable local demo of the shell is in handoff/unified-platform-starter/.

Tenant integrity. Every institution-managed parent has UNIQUE (institution_id, id). Every child uses a composite foreign key, e.g. FOREIGN KEY (institution_id, offering_id) REFERENCES course_offerings (institution_id, id), so a row can’t point into another institution even if application code is wrong. Graders must hold a current teaching assignment; students can’t self-assign authoritative enrollment.

Submission transaction

  1. Authenticate the student.
  2. Validate current enrollment and submission permission.
  3. Confirm the enrollment belongs to the assignment’s offering (composite tenant key).
  4. Bind to the assignment version the student saw.
  5. Validate the expected record version.
  6. Snapshot the selected artifact only — not the private workspace.
  7. Create an immutable submission version.
  8. Persist the receipt and outbox event atomically.

A retry with the same idempotency key returns the existing receipt. A timeout after sending is unknown — not failure or success — until a status check confirms. A local save is not a submission; a submission is not a grade.

Go rule. GO only when every applicable gate passes or has an authorized not-applicable decision; evidence matches the candidate, target, tenant, configuration and data mode; no launch-blocking issue is open; approvals are recorded; and support is active. Silence is not a pass.

Standards notes

  • Say “the HECVAT version the institution requires” and record the exact workbook. HECVAT 4 merges Full, Lite and On-Prem; it is a questionnaire, not a certification.
  • WCAG 2.2 AA is Semester’s engineering target. The DOJ Title II rule specifies WCAG 2.1 AA for covered public entities, with compliance dates in April 2027 or 2028 by entity size. Counsel decides applicability per institution.
  • An accessibility conformance report, a security report, an insurance decision and the customer’s approval are separate artifacts. A signed DPA alone does not establish the school-official conditions.

5. Legacy migration M0–M8

StageNameWhat it requires
M0Inventory and authorizationSource systems + owners, counts, classifications, extraction method, historical scope, retention/holds, destination authority, window. No production extraction before authority.
M1Mapping contractPer field: source → destination, transform, authority class, null handling, timezone, identifier mapping, validation, conflict rule, retention, reviewer. Missing grade ≠ zero; missing enrollment ≠ active.
M2Controlled staging and quarantineRestricted store; manifest, checksum, extraction time; quarantine invalid; staging never visible to students/faculty; cleanup.
M3Canonical identity resolutionMap external person ids to approved memberships; never merge on name; email is a signal not proof; ambiguous → human review; inactive identities create no access.
M4Idempotent transformationStable external keys; source→canonical map; versioned transforms; reruns create no duplicates.
M5Dry-run reconciliationCounts by institution/term/offering/status; referential integrity; deadlines + timezones; submission↔student; released vs draft grades; checksums; permission outcomes. Right count can still be wrong students.
M6Shadow operationLoad without production actions; compare source changes vs projections; dropped students, changed instructors, withdrawn access, deleted source rows; ordering + duplicates.
M7Controlled cutoverPer domain: read-only replication · native ownership · archive. One writer of record. Checkpoint → baseline → final increment → reconcile → data-owner acceptance → enable mode → verify → stabilize.
M8Rollback and closeoutDisable actions on stop criteria; preserve evidence and ids; route to authoritative system; reconcile cutover writes; never “roll back” by deleting rows that gained submissions.

Classify first: student-private (opt-in import), institution SIS/LMS (approved extract), prototype or sample (excluded from production), company records (separate scope), historical academic (preserve meaning, don’t reactivate rosters).
